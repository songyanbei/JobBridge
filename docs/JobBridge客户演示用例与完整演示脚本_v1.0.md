# JobBridge 客户演示用例与完整演示脚本 v1.0

> 用途：面向客户的产品演示、需求确认和验收预演。
>
> 口径：本文只描述当前代码已实现、已测试或有明确开关控制的能力。现场演示优先使用隔离模拟企业微信环境，不连接真实预发布或生产。

## 当前演示环境（2026-08-26）

本脚本以当前正在运行的隔离服务为准：

| 入口 | 地址 | 数据源 | 用途 |
|---|---|---|---|
| 模拟企业微信 | `http://localhost:5174/` | `jb-p11-browser-mysql` | 厂家 / 中介 / 工人对话 |
| 运营后台 | `http://localhost:18080/admin/` | `jb-p11-browser-mysql` | 后台页面 |
| Phase 11 API | `http://localhost:18090/` | `jb-p11-browser-mysql` | 生命周期、替换、清理 API（内部） |

当前隔离后台账号：`admin / Demo@12345`。该密码仅用于本地演示，禁止带入生产。

演示数据准备（仅隔离库）：

```bash
# 统一演示库（对话、后台、Phase 11 共用）
docker exec -i jb-p11-browser-mysql mysql --default-character-set=utf8mb4 -uroot -proot jobbridge \
  < scripts/prepare_demo_data.sql

# 补充“苏州电子厂”7 条剧本岗位（重复执行安全）
docker exec -i jb-p11-browser-mysql mysql --default-character-set=utf8mb4 -uroot -proot jobbridge \
  < scripts/demo_seed_supplement.sql
```

准备完成的验收口径：统一库应有 7 条 `demo_supp_v1` 岗位，且这 7 条均有 `hiring_company`；页面推荐应显示“招聘工厂：…”，不显示“（历史回退）”。两条无公司主体的中介历史岗位可保持空值，并不应被当作有效推荐结果。

## 功能地图

| 系统面 | 当前能力 | 演示入口 |
|---|---|---|
| 企微对话 | 自然语言意图识别、多轮补全、岗位/工人搜索、条件调整、分页、指令和人工客服 | `5174` 双视角 |
| 岗位业务 | 岗位发布、敏感词审核、通过/驳回、续期、招满、下架、恢复和岗位替换 | 厂家 / 中介对话 + 后台 |
| 简历业务 | 简历上传、状态查询、全量更新、新旧 ID 替换、候选/历史/过期状态和删除清理 | 工人对话 + Phase 11 后台 |
| 推荐与隐私 | SQL 硬过滤、排序、快照翻页、角色字段投影、联系方式隔离、匹配依据开关 | 工人 / 中介搜索 |
| 运营后台 | 登录、审核工作台、账号、岗位、简历、字典、配置、报表、对话日志 | `18080/admin/` |
| 生命周期运维 | TTL 到期、候选回收、目标清理、dead-letter 重驱、媒体隔离双人审批、审计 | `18090` API + 清理页 |
| 外部集成 | 企业微信 webhook 验签/幂等/入队、小程序点击事件回传、出站重试 | API / 隔离模拟器 |
| 治理与可观测性 | RBAC、版本乐观锁、软锁、rollout、健康/就绪探针、构建信息、CSV 导出 | 后台 + API |

演示顺序遵循“先跑通一条最小业务链路，再按需展开治理能力”：先展示岗位发布 → 工人搜索 → 简历更新，再展示审核、权限、生命周期和清理，不在现场做大规模故障或真实数据操作。

## 1. 演示目标

用一条完整业务链路说明 JobBridge 如何完成：

1. 厂家发布岗位，系统自动抽取信息并完成审核、上架。
2. 工人和中介用自然语言找岗位/找工人，系统多轮理解、检索、排序和翻页。
3. 对话不完整时继续追问，下一轮只补缺失字段，不要求重复填写。
4. 运营人员在后台完成审核、账号管理、岗位/简历生命周期管理和数据分析。
5. 简历从首次上传到过期、全量更新、替换旧版本、历史留存和清理的闭环可追踪。
6. 角色权限、隐私字段、敏感词、冲突、失败重试和清理门禁均有明确边界。

  jobbridge job user > backups/demo-before-reset.sql

  < scripts/demo_seed_supplement.sql

## 4. 必演主线（约 25 分钟）

### 用例 A：厂家一句话发布完整岗位

**身份**：厂家。

**输入**：

```text
苏州工业园区招20个电子厂普工，男女不限，5500-7000，包吃住，两班倒，长期工
```

**预期**：回复“您的岗位信息已入库，将进入匹配池”。

**后台展示**：岗位管理中查看城市、工种、薪资、人数、食宿、班次、审核状态和有效期。

**客户口播**：厂家只需用自然语言描述岗位，系统将内容抽取为结构化岗位，并把岗位送入匹配池。

### 用例 B：岗位信息不全，多轮追问补齐

**第 1 轮**：

```text
我想发个上海的服装厂岗位
```

**预期**：系统只追问缺少的薪资和招聘人数等必填字段。

**第 2 轮**：

```text
月薪6000-7500，招10个人，包吃住
```

**预期**：岗位入库；后台可看到两轮消息合并后的完整岗位。

**客户口播**：这是有状态的多轮会话，不是简单把两条文本拼接在一起；系统保留已确认字段，只要求补缺失字段。

### 用例 C：敏感内容自动驳回

**输入**：

```text
苏州招10个网管，月薪5000，另外可以代开发票
```

**预期**：回复已收到但未通过内容审核；岗位不上架。

**后台展示**：审核工作台查看驳回原因和审核日志，确认敏感词命中。

### 用例 D：工人自然语言找工作

**身份**：新的工人账号。

**输入**：

```text
苏州找电子厂，5500以上，包吃住
```

**预期**：返回岗位 Top3 或当前候选数量，并提供“更多”和调整条件提示。

**必须强调**：前台只展示岗位基础信息，不展示联系人电话、手机号或内部对象存储地址。

### 用例 E：多轮调整搜索条件

**继续输入**：

```text
工资再高点，7000以上
```

**预期**：保留上一轮城市和工种，只更新薪资条件；返回新的匹配岗位。

### 用例 F：搜索翻页与结果耗尽

**继续输入**：

```text
再来几个
```

**预期**：从上一轮候选快照返回下一批，不重复上一批岗位；候选耗尽后给出收尾提示。

### 用例 G：中介双向找人/找岗位

**身份**：中介。

1. 发送 `/找工人`，预期进入找工人模式。
2. 发送 `深圳男工`，预期返回候选工人或明确无结果提示。
3. 发送 `/找岗位`，预期进入找岗位模式。
4. 发送 `帮一个工人找苏州电子厂的活，5500以上，包吃住`，预期按中介权限返回岗位。

**权限演示**：使用未开通岗位搜索权限的中介账号时，系统应明确拒绝，不返回越权数据。

### 用例 H：首次上传完整简历

**身份**：新工人。

**第 1 轮**：

```text
我要上传简历
```

**第 2 轮**：

```text
28岁，深圳，打包工，男，期望月薪5000
```

**预期**：系统追问缺失字段；字段补齐后简历入库并进入审核/匹配池。

### 用例 I：简历全量更新和新旧版本替换

1. 发送 `/我的状态`，记下在线简历 ID。
2. 发送 `/更新简历 [在线简历ID]`。
3. 预期系统明确提示“从头发送完整的新简历信息”，且不会继承旧字段。
4. 发送：

```text
30岁，广州，厨师，男，期望月薪6000
```

5. 再发送 `/我的状态`。

**预期**：新简历使用新 ID；新版本在线，旧版本进入历史；候选草稿、审核状态和媒体关系可追踪。

### 用例 J：用户自助状态、人工客服和删除

依次演示：

- `/我的状态`：区分账号、在线岗位/简历、候选简历、历史简历。
- `/人工客服`：转人工提示和客服电话占位文案。
- `/删除我的信息`：仅使用隔离测试账号，确认账号进入 deleted 状态，简历清理任务生成并完成。

删除属于不可逆演示动作，必须使用一次性测试账号，并在演示前向客户说明这是隔离环境。

## 5. 厂家操作命令补充

在厂家身份下展示：

| 命令 | 预期 |
|---|---|
| `/续期 15` | 延长最近在线岗位有效期 |
| `/续期 30` | 按允许范围延长有效期 |
| `/续期 7` | 明确提示只支持 15 或 30 天 |
| `/招满了` | 标记最近在线岗位已招满 |
| `/下架` | 下架最近在线岗位 |
| `/更新岗位 [ID]` | 开启岗位替换开关后进入全量更新草稿；开关关闭时明确提示暂不可用 |

`/更新岗位` 是否现场演示取决于本次部署是否打开 `JOB_REPLACEMENT_ENABLED`；默认关闭时不要把“暂不可用”描述为故障。

## 6. 运营后台演示路线（约 15 分钟）

### 6.1 Dashboard / 数据看板

展示今日新增用户、岗位、简历、检索量、审核积压、角色分布、趋势、TOP 和转化漏斗；说明数据来自业务表、对话日志和推荐事实。

### 6.2 审核工作台

1. 查看待审岗位/简历队列。
2. 获取审核软锁，避免多人同时处理。
3. 演示通过、驳回、字段修正和最近一次审核动作撤销。
4. 查看提交者历史和审核原因。

### 6.3 岗位管理

- 按城市、工种、审核状态、生命周期筛选。
- 打开详情查看薪资、人数、有效期、下架原因和版本。
- 编辑、延期、下架、恢复下架。
- 查看岗位替换候选、冲突和取消/重试入口。
- 导出岗位 CSV。

### 6.4 简历管理

- 按在线、候选、历史、过期、下架筛选。
- 查看激活时间、业务到期、候选到期、下架原因、新旧 ID 和关系状态。
- 对允许的状态执行编辑、延期、下架。
- 查看更新候选、冲突原因、取消和重试。
- 导出简历 CSV；演示脱敏字段，不展示正文、手机号、对象存储 key。

### 6.5 账号与字典

- 厂家：预注册、编辑、批量导入。
- 中介：预注册、编辑、批量导入。
- 工人：只读查看。
- 黑名单：封禁/解封和原因。
- 城市别名、工种字典、敏感词新增/删除/批量维护。

### 6.6 系统配置与权限策略

- 业务 TTL 和候选 TTL 范围校验。
- 简历替换 rollout allowlist/cohort 读取和更新。
- 推荐字段可见性策略校验、保存、查看历史和恢复。
- 说明 `operator` 允许查询和常规操作，`super_admin` 才能修改 allowlist、重驱和媒体处置。

### 6.7 清理运维

- 查询目标清理任务、媒体隔离问题和媒体 dead-letter。
- dead-letter 重驱要求理由，每批最多 50 条、每管理员每分钟最多 2 批。
- 媒体处置必须由两个不同管理员审批和执行，自批会被拒绝。
- 展示失败重试、租约、continuation 和最终状态。

### 6.8 推荐策略与对话日志

- 推荐策略版本、发布、回滚和运行时开关。
- 推荐指标总览、自然日曝光和字段策略。
- 按用户和时间范围查看对话日志，必要时导出 CSV。

## 7. 简历生命周期深演（客户关心数据治理时）

使用一份隔离简历按以下顺序展示：

1. 上传后进入候选/审核状态。
2. 审核通过后激活，业务 TTL 从 `activated_at` 起算。
3. 到期任务回收过期简历；搜索和推荐不再返回过期/下架/历史版本。
4. 更新命令创建新 ID，旧 ID 不被原地覆盖。
5. 新候选审核通过后，新版本激活、旧版本转历史。
6. 清理 worker 处理媒体、推荐、关系、会话和 ledger；任一隔离问题/dead-letter/orphan 门禁未清零时，硬删除不允许开启。

**客户口径**：这是可恢复、可审计的生命周期管理，不是定时任务直接物理删除业务数据。

## 8. 安全与异常演示

只选 2～3 个能说明价值的异常，不做巨型故障演示：

| 场景 | 操作 | 预期 |
|---|---|---|
| 角色越权 | 工人发送 `/找岗位` 或厂家执行工人专属命令 | 明确拒绝，不泄露数据 |
| 敏感词 | 发布包含高风险词的岗位 | 自动驳回并保留审核记录 |
| 推荐目标过期 | 过期后提交推荐/出站 | 返回稳定原因 `recommendation_target_stale`，不生成新推荐事实 |
| 替换并发冲突 | 同一简历重复发起更新/审核 | 返回 `replacement_in_progress` 或 `replacement_conflict` |
| 清理失败 | 构造 dead-letter | 可查询、可重驱，硬删除门禁保持关闭 |
| Redis 短暂不可用 | 隔离测试环境停止 Redis | 健康状态和失败重试可观察，恢复后继续处理 |

## 9. 30 分钟客户版流程

1. 2 分钟：产品定位和三类角色。
2. 6 分钟：厂家一句话发布 + 多轮补齐 + 敏感词驳回。
3. 6 分钟：工人搜索 + 薪资调整 + “再来几个”。
4. 4 分钟：中介 `/找工人` / `/找岗位` 和权限边界。
5. 5 分钟：上传简历 + 全量更新 + 新旧版本状态。
6. 5 分钟：后台审核、简历生命周期、清理任务和数据看板。
7. 2 分钟：安全、审计和上线边界说明。

## 10. 10 分钟高层版流程

1. 厂家一句话发布岗位。
2. 工人自然语言搜索并调整薪资。
3. 展示没有联系方式的隐私结果。
4. 展示简历更新后新旧 ID 状态。
5. 后台 Dashboard + 审核工作台 + 简历生命周期筛选。

## 11. 客户验收清单

- [ ] 厂家无需表单即可发布完整岗位。
- [ ] 信息缺失时系统会追问，补齐后只生成一条完整业务记录。
- [ ] 敏感岗位不上架且有可追溯原因。
- [ ] 工人搜索结果符合城市、工种、薪资和食宿条件。
- [ ] 多轮调整只修改用户改变的条件。
- [ ] “更多”不重复已展示岗位。
- [ ] 中介双向模式受权限控制。
