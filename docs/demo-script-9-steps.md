## 第 1 步 · 厂家完整发布

**身份**：厂家 · 朱艳（苏州永利塑胶）

**用户消息**：
```
苏州工业园区招20个电子厂普工，男女不限，5500-7000，包吃住，两班倒，长期工
```

**预期回复要点**：
> "已发布岗位：苏州市 电子厂 5500-7000 元 包吃住 招 20 人。可发送 /我的岗位 查看。"

**演示动作 + 口播**：
- 切到运营后台 → **岗位管理**，按"最近创建"排序，点开刚发布的那条
- 展开**详情**：城市/工种/薪资/headcount/包吃住/班次/审核状态全都从一句自然语言抽出来了
- **口播**："厂家不需要填表单，一句话发出去，模型就把 10+ 个结构化字段全抽出来了，状态默认是 passed 直接上架"

## 第 2 步 · 厂家信息不全 → 多轮追问

**身份**：厂家 · 朱艳（同上）

**第 1 轮发**：
```
我想发个上海的服装厂岗位
```

**预期系统反问**（缺薪资 + 招几人）：
> "好的，再确认两个信息：①月综合收入大概多少？②招几个人？"

**第 2 轮发**：
```
月薪6000-7500，招10个人，包吃住
```

**预期回复**：
> "已发布岗位：上海市 服装厂 6000-7500 元 包吃住 招 10 人。"

**演示动作 + 口播**：
- 后台 **岗位管理** 看到这条新增
- **口播**："注意——这两条消息是分开发的。系统在 30 分钟会话窗内把它们拼成一个岗位入库。多轮上下文是个状态机，不是简单的字符串拼接"

## 第 3 步 · 含 high 敏感词 → 自动驳回

**身份**：厂家 · 朱艳（同上）

**用户消息**：

```
另外可以代开发票

```

**预期回复**：
> "您的岗位信息已收到，但未通过内容审核。如有疑问请联系客服。"

**演示动作 + 口播**：

- 点开看：审核原因带上"代开发票"敏感词标记
- 如需看流水，后台审核日志里会有自动驳回记录
- **口播**："当前演示的是 high 级敏感词自动驳回。`代开发票` 在种子词表里是 high，所以不会进入人工待审队列；LLM 安全检查目前只是预留接入点，真正生效的是敏感词字典规则"

## 第 6 步 · "工资再高点" → 多轮修改

**用户消息**（同一会话，紧接上一步）：
```
工资再高点，7000以上
```

**预期回复**：
返回新的 Top3，薪资区间都能覆盖 7000：
> 1. 苏州高新区电子厂 6500-8500 包吃住
> 2. 苏州昆山电子厂 7000-9000 包吃住
> 3. 苏州吴中电子厂 7500-9800 白班
>
> 还有 4 个候选，可回复"再来几个"。

**口播**：
- "我没有重发城市和工种，只说'工资再高点'。模型在多轮上下文里把上一轮 criteria 累积下来，只更新薪资字段"
- "前一轮的 city=苏州市 / job_category=电子厂 自动保留了——这是多轮对话状态机的核心"
- "再次注意：仍然没有联系方式"

---

## 第 7 步 · "再来几个" → 翻页

**用户消息**：
```
再来几个
```

**预期回复**：
返回上一次结果中没展示过的下一批岗位，最多再展示 3 条，并提示还剩 1 条。

**口播**：
- "这条命令叫 show_more。系统识别后**不会重新跑 LLM 重排**，而是从上一轮的快照里取下一批——省成本、低延迟"
- "比如刚才 7000+ 一共 7 条候选，我们已经看了 Top3，这次返回下一批 3 条，并提示还剩 1 条"

---

## 第 8 步 · "至少 9500" → 薪资区间直接命中（核心亮点）

**用户消息**：
```
工资再高点，至少9500
```

**预期回复**：
> 找到 3 个比较合适的岗位：
> 1. 苏州工业园电子厂 8600-11000 白班 高级技工
> 2. 苏州相城电子厂 8800-11500 白班 资深工程师
> 3. 苏州工业园电子厂 9000-12000 白班 组长

**口播（这一步建议慢慢讲）**：
- "用户提了个更高的条件——苏州电子厂 9500 起。系统不会只看岗位下限，而是看岗位薪资区间能不能覆盖 9500"
- "比如 8600-11000 的岗位，下限低于 9500，但上限覆盖 9500，所以这是符合用户要求的，不应该被错误过滤掉"
- "这一步展示的是搜索语义的准确性：只有真实低召回时才需要自动放宽，不能让 fallback 掩盖过滤 bug"
- "如果要演示自动放宽，要单独构造所有岗位上限都低于原始薪资、放宽 10% 后才命中的数据"

## 关键风险预案

| 风险 | 兜底 |
|------|------|
| LLM 抽取出来的 `salary_floor_monthly` 不是 5500 / 7000 / 9500 整数 | 改用更明确的措辞，例如"工资下限 9500"、"月薪 7000 以上" |
| 第 6 步 LLM 把"再高点"理解为只 +500 → 抽出 6000 | 直接说"7000 以上"，避免模糊措辞 |
| 第 7 步 show_more 没有更多结果（候选池被取空） | 演示前先在 mock 里跑一次预演确认 |
| 第 8 步没有召回 8600-11000 岗位 | 检查搜索 SQL 是否使用薪资区间语义：`ceiling >= D OR (ceiling IS NULL AND floor >= D)` |
| 数据库中文乱码 | 确认 connection 用 utf8mb4，环境变量已设置 |
