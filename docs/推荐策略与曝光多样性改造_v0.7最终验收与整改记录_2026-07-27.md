## 本轮复核确认的实现

### 排序与搜索

- v1 固定召回 50、确定性预评分 Top 20、展示 Top 3；精排池按 pre-score 和稳定 hash 排序，LLM 输入顺序与 `precision_pool_ids` 一致。
- 预评分、匹配分、薪资适配、缺失分量重归一、硬过滤契约、LLM rank→semantic 映射和两组固定向量已固化。
- 多样性贪心会返回已开放 repeat bucket 的全部候选，不再按 SQL 输入顺序提前截断；owner limit、near/ordinary 分层、探索第三位替换和稳定 tie-break 均有回归覆盖。
- 岗位和简历字段投影已补齐，legacy/v1 失败都会经过确定性或 legacy rerank，不会静默落回未经重排的 SQL 顺序。
- 自动放宽、确认放宽和 `show_more` 继续保持既有语义；show_more 按快照 ID 顺序恢复，kill switch 会使 v1 快照失效并用 legacy 重建。
- 初始查询、每个放宽探查、最终采用查询都会产生 attempt 事实；自动放宽使用同一最终 request，`served_attempt_id` 只指向实际采用的 attempt。

### Shadow、LLM 与控制面

- shadow 使用独立 asyncio runner、有界队列、进程内并发、Redis 全局 permit 和方向级 token 预算；Redis 不可用时 fail-closed。
- deadline 在提交 runner 前建立，排队、HTTP 阶段和完整 async await 共用绝对截止时间；provider 不重试，Qwen/豆包均透传 `call_policy`。
- shadow 只有在 served request/outbox 事务成功后才激活持久化；持久化使用独立有界 executor，失败或队列满不阻塞 legacy 回复。
- provider 未返回 usage、超时或连接错误时按悲观 input/output token 上限记账；已知较低 usage 才退还差额。
- 稳定 v1 和 shadow 候选共用同一个 `scoring_time_utc`，避免跨北京时间日界线或 168 小时边界出现两侧口径漂移。
- runtime control 具备 DB 真源、Redis write-through/Pub/Sub、5 秒轮询、revision 单调更新和双后端不可用时的 fail-safe legacy。

### 事实、投递、曝光、隐私和报表

- off、shadow、on、legacy、零结果和 show_more 耗尽均有 request/attempt 事实；真正有候选的回复才创建 delivery，避免虚假曝光。
- delivery 使用 AES-GCM、AAD 绑定 delivery/user/purpose、key ring/version；session patch、conversation log 和 Redis history 不保存推荐正文。
- delivery 状态机使用 `prepared/pending/sending/retry_wait/sent/permanent_failed/unknown`；企微返回的 msgid 和 invalid recipients 均被保存，发送成功后才派生 impression。
- dispatcher、session reconciler、impression deriver 使用独立恢复线程；曝光明细幂等、数量核对、日聚合可重算，TTL 和候选删除会清理 request/attempt/delivery/impression/event/daily 及 JSON 引用。
- 点击只在 sent 且有 impression 事实时 attributed，并由数据库去重键保证幂等；指标使用 request/attempt/impression/event/delivery 的固定真源。
- `shadow_persistence_dropped` 目前是结构化日志事实；由于没有日志指标后端可在本地查询，API 对 `persistence_drop_count`、provider 限流率和成本单价返回“无数据”而不是伪造 0，前端也显示为缺失来源。

### 策略后台和模拟

- 三个官方模板、八项参数范围与权重和校验、不可变发布版本、release history、候选/全量/回滚、RBAC、kill switch 和审计已落地。
- 模拟使用生产候选查询、曝光读取、Top 20 precision pool 和 `recommendation_simulation` LLM 标记；stable 为空时会额外执行真实 legacy 候选数/Top N/LLM 重排，而不是把 SQL 原始顺序冒充线上策略。
- 前端编辑、模拟、版本历史、指标、灰度/回滚确认和权限显示已完成，`npm run lint` 与 `npm run build` 通过。

6. 为结构化日志中的 `shadow_persistence_dropped`、provider 429/限流和 token 单价接入线上指标聚合；接入前报表中的相应字段必须保持“无数据”。
